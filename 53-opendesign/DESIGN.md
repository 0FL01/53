## 1. Direction

Привычная структура личного мессенджера, похожая по удобству на Telegram, но спокойнее и строже. Главное — переписка, понятная очередь отправки и осознанное доверие контакту. Не сетевой терминал, не VPN-панель и не маркетинговый сайт.

Название в макете — **53**. Это существующее кодовое имя проекта, не новый бренд. Схема ссылок остаётся `dmsg://`. Не копировать логотип Telegram, его иллюстрации или ресурсы.

Все экраны — светлые. Прямые углы абсолютно у всех элементов приложения: сообщения, аватары, кнопки, поля, диалоги, меню, панели, бейджи. `radius = 0`, `elevation = 0`. Нет теней, градиентов, glassmorphism, фоновых узоров, pill controls и плавающего круглого FAB. Системная клавиатура, системные разрешения и физическая форма телефона не принадлежат дизайн-системе приложения.

## 4. Layout

Контрольный размер HTML 390 × 844 CSS px; проверить 360 и 412 px по ширине. Это координаты макета, а не универсальное соответствие CSS px и физических пикселей Android. При реализации геометрия в dp, текст в sp.

Отступы: 4 / 8 / 12 / 16 / 24 / 32. Боковой отступ 16. Toolbar 56 dp. Минимальный touch target 48 × 48 dp. Строка диалога минимум 76 dp; квадратный аватар 44 dp. Поле и кнопка минимум 48 dp.

Белый фон; списки на всю ширину с тонкими разделителями, а не набор карточек. Без нижнего tab bar: основной экран один — диалоги. В toolbar: меню, название, добавление контакта. Поиск возможен только как помеченное расширение по локальным данным, не поиск пользователей по серверу.

На экране чата: назад, идентификатор/локальное имя, переход к карточке контакта. Внизу текстовое поле и квадратная кнопка отправки. В текущем контракте нет скрепки, микрофона, трубки, видеозвонка и emoji-store. В целевом дизайне добавлена трубка в toolbar по CALLS_SPEC.md. Это будущий звонок, не голосовое сообщение; composer не меняется. Composer учитывает клавиатуру и нижние системные отступы; toolbar учитывает верхние insets. Не рисовать собственную iOS-клавиатуру.

## 5. Components

### DialogRow
Квадратная плитка с инициалами локального alias либо первыми символами ID. `DialogSummary` уже возвращает `local_alias`, `preview`, `last_local_timestamp_ms`, `local_unread`, `read_cursor`, `has_keys`, `identity_mismatch`, `state`, `contact_id`. Alias необязателен; ID остаётся доступен в карточке. Empty dialog не имеет preview/time. В обоих режимах HTML эти поддерживаемые поля представлены синтетическими примерами. В нативном UI показывать только полученные значения, без выдуманного времени или unread.

Диалоги упорядочены по локальной активности descending, contact ID ascending при равенстве. Alias/read/status/trust changes не поднимают строку. Локальное время — время этого устройства при queue/decrypt, не время отправителя или last-seen. `local_unread` относится только к входящим строкам за read cursor; `mark_read` применяется по реально просмотренной строке, без отправки read receipt.

### MessageBlock
Прямоугольник без хвостика. Входящее слева (#F1F4F6), исходящее справа (#EAF3FA). Максимальная ширина 86% доступной области. Внутренние отступы 10–12 по вертикали, 12 по горизонтали. Время — только при наличии данных. Длинный ID или слово не ломает ширину.

Статусы исходящего сообщения:
- queued → «В очереди»: ядро уже сохранило сообщение для повтора;
- accepted → «На сервере»: сервер принял сообщение;
- delivered → «Доставка подтверждена сервером»: это не прочтение и не криптографическое подтверждение расшифровки;
- ошибка вызова без подтверждённой постановки в очередь → «Не отправлено», текст остаётся в composer.

Точный статус уже доступен в `HistoryMessage.delivery_state` и `message_status(message_id_hex)`: queued → accepted → delivered, persistent и monotonic. Incoming имеет `None`, неизвестный ID возвращает `None`; в outgoing UI это «Статус пока неизвестен». Delivered сохраняется в истории после удаления outbox. Не выводить delivered из отсутствия строки в `outbox()`. Никаких синих галочек прочтения.

Защищённая persistent история обеих сторон доступна через `history_page(contact_id, before_local_id?, limit)`. Страницы newest-first по local ID descending; для хронологической ленты reverse каждой страницы и prepend более старых. Чтение страницы не отмечает её прочитанной. Core владеет БД и шифрованием текста/alias; plaintext не дублируется в prefs или логах.

### ConnectionStrip
Одна спокойная строка под toolbar: DNS, проверка, ошибка или «Фоновая связь выключена»; нажатие открывает «Связь». R19 `ConnectionUiState`/`ConnectionFacts` по actual worker outcomes, `dnsStatus()` — диагностика. FGS/таймер не доказывают сеть. Device actual check/FGS stop verified; в HTML «DNS · демо-состояние», last-success timestamp не выдумывается.

### SafetyBanner
Прямоугольная предупреждающая область в потоке экрана, с заголовком и объяснением. При `identityMismatch` composer и retry заблокированы. Действие ведёт к проверке, а не молча подтверждает новый ключ.

Смена ключа: «Ключ контакта изменился. Отправка приостановлена. Свяжитесь с человеком другим способом и повторно проверьте его QR». Отдельное подтверждение; нет кнопки «Игнорировать и отправить». Не рисовать старый/новый fingerprint как доступную функцию: facade его не отдаёт.

### Controls
Прямоугольные кнопки с текстом, квадратные checkbox/radio-представления, квадратные аватары и бейджи. У иконки 20–24 dp область нажатия 48 dp. Линейные SVG/векторные пиктограммы, единая толщина. Нет декоративной иконки сети у каждого сообщения.

### Modal / sheet
Нулевой радиус, белый фон, тонкая граница. Нативный bottom sheet может использоваться при адаптации, но без скруглённых верхних углов. Небольшое затемнение scrim допустимо. Отмена всегда доступна; опасная кнопка не стоит первой и не предвыбрана.

## 6. Navigation and screens

Основной экран «Диалоги» → «Чат» → «Контакт». «Добавить» → «QR / ID». Меню → «Мой QR», «Связь», «Очередь», «Хранилище». Первый запуск → вставка/скан публичного `dmsg://server/` → offline preview → явное принятие профиля → короткий pinned DNS policy request → «Войти» / «Создать аккаунт».

Профиль содержит домен, полный DER-сертификат и публичный Noise-ключ, не token. Preview не выполняет сеть и не регистрирует аккаунт. Основные CTA: «Вставить код сервера», «Сканировать QR», «Использовать этот сервер», затем вход/создание. При отказе камеры остаётся вставка. Контактный QR — отдельный путь.

Policy: `open` / `invite_only` (закрытый default). Пока ответ не получен или ошибочен, signup заблокирован. Поле приглашения существует **только** в signup + invite_only; в login и open signup отсутствует. Логин 3–32 ASCII `[a-z0-9_.-]`, ASCII-регистр приводится к нижнему без trim. Пароль 8–128 байт UTF-8 без управляющих символов, без trim/нормализации; по умолчанию скрыт, reveal явный. Успех/отмена очищают временный пароль и приглашение; resume — только ключом.

Новый ключ + LOGIN с password proof → challenge без замены. Отдельный экран объясняет: прежний ключ отключится, контактный ID сохранится, ключи станут новыми, старая локальная история не восстановится. Только «Заменить устройство» выполняет второй LOGIN с `expectedDevice`. Отмена/назад до confirm не выполняют второй запрос и не меняют binding. После отправки confirm повтор/отмена заблокированы до ответа; CAS-конфликт требует нового proof и нового согласия, без автоповтора.

Обязательные состояния: пустой список, нет native core, loading/error/retry, requested/accepted/blocked/identityMismatch, профиль invalid, policy loading/error/open/invite_only, login/signup pending, replacement challenge/pending/cancel/conflict, key-resume revoked, typed auth errors, запрещённая камера, уведомления выключены, FGS выключен, нет DNS, queued/accepted/delivered/unknown, lost Keystore. Не превращать сценарии QA в постоянное production-меню.

## 7. Product boundaries

Граница UI — `CODE_REVIEW.md`, `HANDOFF.md`, R18 API (`../crates/core/R18_API.md`). R19 Kotlin/AppCompat/XML прошёл JVM/build и separate physical frontend/recursive DNS acceptance; это не проверка media/полной аппаратной матрицы. HTML только для дизайна, не WebView в APK.

Только личные текстовые чаты. В текущем контракте нет групп, каналов, звонков, файлов, голосовых сообщений, stories, stickers, typing, online/last seen, публичного каталога, cloud backup, мультиаккаунтов и multi-device. Заготовки в сервере/roadmap не считаются работающими действиями. Исключение для дизайна: по запросу пользователя звонки включены в целевой прототип, но скрыты из режима текущего контракта и production до появления API.

Runtime — DNS с закреплённым публичным профилем. Нет ENROL, join/token fallback, DirectTCP runtime или old-schema migration. Политика фонового опроса не гарантирует доступность. Новая offline-сессия не может гарантированно отправить первый текст без связи. Блокировка контакта в текущем core терминальна; «Разблокировать» не рисовать.

## 8. Accessibility and behavior

48 dp минимальная область нажатия; keyboard/focus/TalkBack labels; сообщения состояния объявляются без чтения секретов. Текст и пользовательские сообщения вставляются безопасно, не через неэкранированный HTML. Уважать reduced motion; без looping animations. Состояние pending блокирует повторное действие. При network error черновик не теряется. Поле принимает многострочный текст; лимит считается как **4096 байт UTF-8**, не 4096 символов.

Не обрезать сообщения фиксированной высотой. В ленте scrolling, composer остаётся видимым. Публичный ID можно копировать; пароль, приглашение, приватные ключи и raw DNS-запросы не выводить в логи/уведомления. Поле приглашения — только явный signup-ввод, не серверный профиль.

## 9. Acceptance

Все app-owned углы = 0. Только светлая тема. Никаких iPhone/Dynamic Island/serif. Основной экран узнаётся как мессенджер. Нет неподдерживаемых действий. Различаются очередь, принятие сервером и ошибка. Мismatch реально останавливает отправку. Не обещано восстановление после переустановки. Данные-примеры явно обозначены. Проверены узкий экран, длинные строки, большие шрифты и пустые/error состояния.

## Дополнение v2: звонки

Личные аудиозвонки используют ту же светлую систему. Аватар 96 dp, имя 28 sp, длительность 27 sp с табличными цифрами. Mute, endpoint и чат размещены в плоской сетке; hangup в отдельной красной нижней полосе, минимум 56 dp. Ответ зелёный, отклонение контурное красное. Никаких декоративных волн, круглых control buttons или нового набора стилей.

Входящий, установление, разговор, обрыв, системная пауза и завершение являются фазами одного экрана. Полоса текущего вызова общая для приложения. Журнал входит в меню, не требует новой нижней навигации. Видео отдельно и скрыто по умолчанию.

При 200% текста разрешены переносы и вертикальная прокрутка. Контент не сжимается друг на друга, область завершения остаётся доступной. На крупных шрифтах кнопки ответа могут перестраиваться в вертикальный ряд. Системные Android-окна исключены из требования radius 0.

Полные правила: `CALLS_SPEC.md`; нативная граница и источники платформы: `CALLS_HANDOFF.md`; состояния: `calls-state-machine.json`.
