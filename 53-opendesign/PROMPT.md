# Готовое задание для OpenDesign

Создай интерактивный HTML-прототип Android-мессенджера **53** (рабочий протокол `dmsg`) по `DESIGN.md`, `CODE_REVIEW.md`, `CALLS_SPEC.md` и `CALLS_HANDOFF.md` из этой папки. `prototype.html` — исходный визуальный референс, его можно улучшать. Нужен интерфейс приложения, не лендинг, не презентация и не админ-панель.

## Цель

Удобство и ясная структура личной переписки как у Telegram, но более минималистичный, прагматичный, спокойный интерфейс. Только светлая тема. Абсолютно все app-owned углы прямые: `border-radius: 0`. Нет теней, градиентов, круглых аватаров, pill buttons, округлых пузырей и floating action button. Telegram — ориентир удобства, не объект копирования брендинга.

## Приоритеты и среда

Следуй этому brief и `DESIGN.md`. Не применяй без изменений встроенный шаблон `design-templates/mobile-app/SKILL.md`: его iPhone 15 Pro, Dynamic Island, serif-заголовки и ограничение одним экраном противоречат задаче. Создай самостоятельный мобильный HTML prototype с несколькими связанными экранами. Никакого iOS chrome. Декоративная рамка телефона не нужна.

Viewport 390 × 844, адаптация на 360 и 412 px; единицы Android-хэнд-оффа dp/sp. Язык всех пользовательских надписей — русский. Шрифты Roboto/system sans, моноширинный только для ID/отпечатков. Никаких внешних шрифтов, stock-фото и сетевых изображений. Квадратные плитки с символами ID вместо фотографий.

Цвета: фон #FFFFFF, основной текст #17212B, вторичный #5B6773, акцент #246DA8, исходящие #EAF3FA, входящие #F1F4F6, разделители #DDE3E8. Технические поля не должны занимать главный экран. Отступы кратны 4, базовый 16. У иконки размер 20–24, touch target минимум 48. Строки списков отделяются линиями, не тенями.

## Существующий продукт

Прочитай CODE_REVIEW.md. Это Android Kotlin/AppCompat/XML оболочка с Rust core через UniFFI. Compose упомянут в архитектуре, но не подключён в текущем app build. Не выдавай HTML за готовый APK и не предлагай вставить его в WebView. Задача не включает переписывание протокола, backend, транспорта, криптографии, Keystore или generated bindings.

R17 актуально: личный текст; public server profile `dmsg://server/` (domain/fullDER/Noise public, без token), paste/scan → offline preview → accept → pinned DNS policy → login/signup; invitation только signup invite_only; replacement challenge → второй LOGIN с expected-old key только после согласия; key-only resume. Также contact QR `dmsg://contact/`, ID-контакты, consent/block/identity confirm, outbox/retry, FGS и локальный encrypted snapshot в пределах одной установки. Не возвращай ENROL/join/token/DirectTCP runtime/old-schema migration.

R18 реализован (core schema6, 65 all-targets green и Kotlin bindings generated по evidence координатора): encrypted bidirectional history, exact persistent status, DialogSummary/local alias/time/unread/read cursor. Exact API — `../crates/core/R18_API.md`. R19 native AppCompat/XML реализован, 35 JVM/compile green; device runtime pending. Не объявляй browser QA физической frontend acceptance.

Нет в доступном frontend-контракте: звонков, вложений, голосовых, групп, каналов, stories, stickers, typing, presence, read receipts, публичного поиска людей, multi-device, облачного восстановления. По отдельному запросу пользователя звонки теперь проектируются как будущая функция, согласно CALLS_SPEC.md. Остальные перечисленные кнопки не добавляй даже как украшение. Не выдавай дизайн звонков за существующий API. Contact block терминален: без «Разблокировать».

## Два уровня достоверности

Сделай переключатель **вне мобильного интерфейса**: «Целевой интерфейс» / «Текущий контракт».

В целевом варианте также доступны будущие личные аудиозвонки; видео отделено выключенным по умолчанию capability. В режиме текущего контракта скрыты все call-действия, журнал, call-события, media lab и call-board. В обоих режимах доступны реализованные R18 local aliases, локальное время, previews, local unread и bidirectional history. Рядом с макетом явно написано: «R18 API реализован; все значения HTML синтетические. Device runtime pending». Future media не является текущим API.

В режиме текущего контракта необязательный local alias заменяет display label, исходный contact ID остаётся доступен. Empty dialog не имеет preview/time. History newest-first local ID descending: reverse каждой страницы, prepend older; page read не двигает read cursor. Incoming delivery state `null`, outgoing exact Queued/Accepted/Delivered; `message_status` unknown/incoming-only ID → `null`, не delivered. Local time не sender time/last-seen, local unread/read cursor не read receipts. Все plaintext/alias хранятся защищённо ядром; значения HTML — только память страницы. Геометрия и качество интерфейса сохраняются.

## Экраны

1. **Диалоги**. Белый toolbar: меню, 53, действие добавления. Под ним компактная строка состояния связи. Квадратные аватары, имя/ID, превью только при наличии данных, тонкие разделители. Без нижнего tab bar. Empty state: «Пока нет диалогов», кнопка «Добавить контакт». Loading и ошибка загрузки с retry. Локальный поиск — только как явно отмеченное расширение, не поиск пользователей по серверу.

2. **Чат**. Назад, local alias/ID, переход к карточке. Белый фон, прямоугольные сообщения без хвостиков, слева incoming, справа outgoing. Внизу многострочное поле и квадратная send-кнопка. Exact queued/accepted/delivered/unknown и ошибка операции; локальные timestamps доступны в текущем R18 API. Подгрузка history reverse/prepend, mark_read только по реально просмотренной строке. Отправка текста в локальную демо-ленту, но никогда не в сеть. 4096 байт UTF-8: считать байты, не символы; empty/over-limit disables send. При ошибке черновик не пропадает. Статус и количество исходящих не превращаются в unread.

3. **Добавить контакт**. Основной путь «Сканировать QR», дополнительный — ID из 12 символов. Форматирование ID группами по 4 только визуальное, в core передавать непрерывный ID. ID сам по себе не пароль и не подтверждение личности. Создание requested-записи не называй отправленным сетевым запросом.

4. **QR-сканер**. Квадратная область камеры, краткая инструкция, закрытие. В прототипе не запрашивай камеру: явный placeholder «Демонстрация камеры». Server scan ведёт в offline preview, contact scan — в карточку; permission denied даёт вставку публичного кода. Реальный server/contact payload не генерировать. Если рисуется QR, он кодирует DEMO-текст и подписан как образец.

5. **Проверка контактного QR / карточка контакта**. ID, состояние, доступное действие. requested+keys → явное согласие; requested без ключей → сканирование QR. При blocked — ясное объяснение без разблокировки. Profile и contact card разделены, не оставлять четыре опасные кнопки управления чужим ID на экране собственного QR.

6. **Смена ключа**. Красно-янтарный спокойный banner: «Ключ контакта изменился. Отправка приостановлена». Composer и retry неактивны. Объяснение проверки другим каналом, повторный scan QR и отдельное осознанное подтверждение. Без «Игнорировать». Не показывать недоступные через facade старый/новый fingerprint как реальную возможность.

7. **Мой QR**. Собственный ID, квадратный QR на белом поле, копирование публичного ID. Не показывать телефон, пароль или секреты. Демо-QR не должен регистрировать устройство.

8. **Связь**. DNS runtime, public profile и pinning. R19 `ConnectionUiState` по worker outcomes реализован; строковый `dnsStatus()` — диагностика, FGS отдельно. Нет гарантии 24/7 и synthetic last-success timestamp. Кнопка повторной проверки, выбор public profile, read-only публичные параметры. Resolver automatic; обычного ручного addr/crypto ввода нет. В HTML связь искусственная; device runtime pending.

9. **Очередь**. В queued: «Ожидает отправки»; accepted: «Принято сервером». Retry повторяет те же сообщения, не создаёт новые. Не менять accepted на delivered по таймеру в якобы реальном режиме; любые демо-переходы явно обозначены. Не заявлять точный total по первой странице max 100.

10. **Хранилище**. Очистка кэша (не истории), локальный snapshot, восстановление только при подходящих условиях этой же установки. Предупреждение о потере Keystore после переустановки. Нет cloud backup, восстановления на другом телефоне и кнопки сброса account для красоты. Подтверждение перед destructive действиями.

11. **Первый запуск / профиль / аккаунт**. «Выберите свой сервер». Paste/scan → offline preview → «Использовать этот сервер» → policy → login/signup. `open` не имеет invitation; closed default `invite_only`, приглашение только signup. Loading/error не открывают signup. Пароль скрыт, без trim/normalization, 8–128 UTF-8 bytes; login 3–32 ASCII без trim. Typed errors и pending предотвращают повтор. Новый device LOGIN возвращает challenge без mutation: cancel сохраняет старый binding, explicit confirm выполняет второй LOGIN(expected-old key), CAS conflict требует нового proof/согласия. Тот же contact ID, новые ключи, без восстановления истории. Resume только ключом.

## Дополнительные экраны будущих звонков

12. **Журнал звонков**: все/пропущенные, детали по тапу строки, отдельная трубка, пусто/loading/error/retry.
13. **Экран звонка**: incoming/dialing/ringing/connecting/active/reconnecting/system-held/ended; mute, маршруты, сворачивание, итог и сохранение черновика.
14. **Детали звонка**: время, направление, тип, результат, длительность состоявшегося разговора; перейти в чат, позвонить, удалить локальное событие.
15. **Уведомление Android**: схема входящего/текущего/пропущенного, блокировка с приватным именем, канал отключён, нет fullscreen, stale notification.
16. **Настройки звонков**: принимать от принятых контактов, privacy блокировки, отдельная экономия медиа, системный канал, разрешения, очистка журнала.
17. **Разрешения звонков**: микрофон, камера только при видео, отказ/постоянный отказ/отзыв/late callback. HTML не открывает настоящие разрешения.
18. **Предпросмотр видео**: отдельный будущий этап. Явное включение камеры и аудиопуть без видео. Не включать камеру автоматически при согласии другой стороны.

Полное дополнение: `CALLS_PROMPT.md`. Оно заменяет прежний запрет на дизайн звонков, но не расширяет фактический текущий контракт. Не рисовать многолинейный телефон, запись, группы или экранный шаринг.

## Семантика статусов, которую нельзя менять

queued = ядро подтвердило локальное сохранение; accepted = сервер принял; delivered = сервер подтвердил доставку, не прочтение и не гарантия расшифровки. После timeout нельзя автоматически заявлять queued, пока ядро не подтвердило сохранение. Первый offline send без существующей сессии может завершиться ошибкой: оставить текст и объяснить необходимость соединения.

Публичный ID/ключ сервера можно показывать. Приватные ключи, invite token, raw DNS и содержание переписки не выводить в логах и уведомлениях. Никогда не читать реальные секреты из `.local`, `.env`, сертификатов, signing files, баз данных и `.git` ради моков.

## Интерактивность и deliverables

Создай самодостаточный `index.html` с локальным CSS/JS или встроенным CSS/JS, чтобы его можно было открыть офлайн и в preview OpenDesign. Все основные переходы и кнопки демонстрируют понятное локальное поведение. Данные только в памяти. Не нужны сетевые запросы, backend и API keys. Без npm/CDN зависимостей.

Сохрани существующее будущее call-demo и его тесты без расширения медиа. Приоритет R17 — text/auth; будущие call-действия, lab, deep links и call-board скрыты/заблокированы в текущем контракте. `prototype.html` и `index.html` должны быть byte-identical. В `HANDOFF.md` используй текущие подтверждённые R18 encrypted bidirectional history/exact status/summaries/local alias/time/unread API из `../crates/core/R18_API.md`; отличай реализованные storage/native API от синтетических HTML данных и ещё pending device runtime acceptance.

Проверь визуально 360 / 390 / 412 px, большие шрифты, длинное русское сообщение, отсутствие горизонтального overflow, корректный focus, клавиатуру/системные insets и 48 px tap targets. Ни один основной CTA не должен вести в пустоту. Без округлых углов во всех состояниях. Сначала доведи список диалогов, чат и связь; остальные экраны используют ту же систему, не придумывают новые стили.

Результат — файлы прототипа и Android handoff. Не ограничивайся текстовым описанием концепции.
